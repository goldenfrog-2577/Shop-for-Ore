# ⛏️ Shop for Ore by GoldenFrog

Техническая карта-симулятор для Minecraft Bedrock Edition.

**Текущая версия:** 0.2.0 (18 октября 2026), в разработке — 0.3.0. История изменений — в [CHANGELOG.md](CHANGELOG.md).

Проект сочетает в себе:
- сложную экономическую модель,
- систему прогрессии инструментов,
- полную мультиязычность.

## 🎯 Для кого эта карта?
- Игрокам, которым важны механики и прогрессия
- Разработчикам карт, изучающим Script API и функции (`.mcfunction`)

## ⚙️ Технологии
* **Основная логика**: функции `.mcfunction` (цепочки команд)
* **Скрипты**: Minecraft Script API (JavaScript) — меню, команды чата, регистрация, античит
* **Движок**: Bedrock, `min_engine_version` 1.19.50
* **Script API**: `@minecraft/server` 1.1.0-beta, `@minecraft/server-ui` 1.0.0-beta, `@minecraft/server-gametest` 1.0.0-beta
* **Перевод**: файлы `.lang` (русский, английский, украинский, испанский)

> ⚠️ Аддон использует **бета-версии** Script API времён 1.19.50. Новые версии Bedrock старые бета-модули не загружают, поэтому там скрипты (меню, чат) без переноса на современный Script API работать не будут.

## 🌟 Ключевые системы

### 🔄 1. Перерождения (ребитх)
Сделаны функцией `functions/upgrade/upgrade_rebirth.mcfunction`.
* **Условие**: доступно с 16 по 25 уровень, не больше 5 перерождений.
* **Постоянная награда**: эффект «Спешка» I–V по числу перерождений.
* **Оповещение**: сообщение всем игрокам в чат и звук при первом перерождении.
* **Сброс прогресса**: обнуляются уровень, опыт, деньги и зачарования; счётчик перерождений сохраняется.

### 🔨 2. Кирка, растущая с уровнем
Кирка под уровень игрока выдаётся сама (`functions/system/pickaxe_lvl.mcfunction`, раз в секунду) и меняется только при смене уровня или если её нет в слоте.
* **Закреплена в слоте**: компонент `item_lock` (`lock_in_slot`) — кирку нельзя выбросить или переложить.
* **Что можно копать**: 18 ступеней кирки на 25 уровней, у каждой свой список `can_destroy` — от земли до аметистового кластера.
* **Не теряется при смерти**: компонент `keep_on_death`.
* **Не ломается**: `scripts/system/tools.js` следит за прочностью и, когда игрок не копает (или износ больше 90 %), выдаёт новую целую кирку.

### 📊 3. Экономика и интерфейс
* **Автопродажа** (`functions/system/autosale.mcfunction`): игрок встаёт на золотой блок, и руда превращается в деньги и опыт с учётом бустов x2/x4.
* **Бусты и прокачка**: общие бусты x2/x4, личный «Магнит руды» (5 минут, предметы рядом летят к игроку), VIP, зачарования (эффективность до 5, удача до 3), наборы для PvP.
* **Зачарования** (`scripts/menu/enchant_shop.js`, Магазин → Зачарования): один экран выбора — кирка уровня (с текущими уровнями эффективности и удачи) и каждый меч, лук и предмет брони из инвентаря (с текущими зачарованиями; меню само занимает руку, надетую броню нужно снять). Для меча, лука и брони — острота, заговор огня, отдача, защита, шипы, невесомость, сила, отбрасывание, бесконечность; для трезубца — верность, пронзатель, тягун, громовержец; для арбалета — тройной выстрел, пронзание, быстрая перезарядка; щиту и всем остальным — прочность и починка. Несовместимые зачарования (тягун с верностью и громовержцем, тройной выстрел с пронзанием) магазин не предлагает. **Громовержец** (`scripts/system/trident.js`): брошенный трезубец с ним бьёт молнией в поражённого игрока при любой погоде. Каждая покупка +1 уровень до ванильного максимума, цена = базовая × новый уровень (острота I — 5 000, починка — 40 000). Кирка уровня зачаровывается по-прежнему через «Эффективность» и «Удачу».
* **Косметика** (`scripts/menu/cosmetics_shop.js`, Магазин → Косметика): за VIP-коины — цвет ника (в чате и над головой; цвета ролей — только своей роли), цвет текста в чате, частицы-след в движении (8 видов; стоящему на месте — нет), облако частиц 2×2 на месте смерти (6 видов) и свои частицы при продаже на золотом блоке вместо стандартного тотема (7 видов, среди них «Лава», раньше бесплатная у VIP; тег `fx:sell` отключает стандартные строки в `autosale`). Смотреть Косметику может каждый, покупать — только VIP (уровень 26; у заголовка и разделов пометка «[Только для VIP]»); купленное раньше выбирается и без VIP, кроме частиц при продаже — они действуют только у VIP. Покупка — как в магазине, сразу и с сообщением в чат; купленное (тег `cosmetic:<вид>:<id>`) выбирается и снимается бесплатно (`chat:name_color` / `chat:text_color`, `fx:trail:<id>` / `fx:death:<id>` / `fx:sell:<id>`); выбранные частицы без покупки не действуют. Идея магазина — по мотивам карты FearCube, код свой.
* **Ивенты**: «Ускорение», «Золотой дождь», «Подарок» и «Мистик» по таймерам; по умолчанию выключены, включаются переключателями в меню администратора («Бусты и ивенты» → «Ивенты по таймеру») или командой `/scoreboard players set <haste|rain|gift|mythic> settings 1`; администратор может запустить любой сразу командой `!event` или из меню.
* **Мистик** (`scripts/system/mythic.js`): раз в 10 минут (если включён `mythic` в `settings`) сундук в центре PvP-арены (x 300, z 300; высоту скрипт находит сам) очищается и наполняется 4–6 случайными редкими предметами: зачарованное золотое яблоко, тотем, незеритовый слиток, жемчуг Края, взрывные зелья (исцеление, регенерация, сила, скорость), стрелы с эффектами (медлительность, моментальный урон II, отравление, слабость, иссушение, замедленное падение), щит, трезубец, арбалет, алмазы и др. Только здесь выпадает **портативный кристалл Энда** (`server:portable_ender_crystal`, жёлтое название; `items/weapons`, снаряд `entities/thrown_ender_crystal.json`): бросается как снежок, при попадании — взрыв силы 6, как у кристалла Энда, без разрушения блоков и огня; урон тем больше, чем ближе взрыв к ногам цели (так считает урон сама игра). Бросать можно только на PvP-арене (`scripts/system/pvp.js`). Нужна экспериментальная функция «Holiday Creator Features» — в мире она включена. Взрывные зелья и арбалет античит больше не удаляет, оседающие зелья — по-прежнему. Столбец сундука держит прогруженным ticking area `mythic`.
* **Таймеры**: `tick.json` запускает только `system/system`, `system/levelup_check` и планировщик `system/timers`, который вызывает `timers/ticks_N` раз в N тиков (счётчики — фейковые игроки `tN` в табло `timer`) (5, 20, 40, 80, 500, 600, 3600, 4800, 6000).
* **Панели на экране**: слева — профиль, деньги, опыт, уровень, перерождения и онлайн с иконками; справа вверху — табло (название карты, идущие бусты; `ui/scoreboards.json` и фон `textures/ui/server/server_scoreboard_entry` — до 0.3.0 это был отдельный пак `server-ui`).

### 🏆 4. Достижения, мини-игры, музыка
* **Достижения** (`scripts/system/achievements.js`, Меню сервера → Достижения): 16 зелёных достижений и 8 фиолетовых испытаний, как в Java Edition — уровни, VIP, ребитхи, сломанные блоки, накопленные монеты и VIP-коины, зачарование, косметика, перевод монет, победы на PvP-арене и в мини-играх, время в игре, все частицы-следы. Награды — монеты, VIP-коины, опыт, предметы (золотые яблоки, незерит, тотем). Получено — тег `ach:<id>`; счётчики — табло `stat_mined`, `stat_kills`, `stat_deaths` (смерти от игрока или на PvP-арене — для K/D), `stat_playtime` (минуты), `stat_wins` (все мини-игры), `stat_win_<игра>` (`stat_win_pvp_ffa`, `stat_win_spleef`) и тег `stat:paid`. Проверка раз в секунду; за раз — одно достижение, следующее — когда погаснет плашка. При получении: плашка над хотбаром, звук (`random.levelup`, у испытаний — `minecraft.challenge.complete`), сообщение всем в чате. В меню — список с прогрессом («1 234 / 10 000»), у каждого — условие и награда. Вайп снимает достижения у игроков в сети. Администратор: `!achievement <ник> list|grant|revoke [id]`.
* **Плашка над хотбаром** (`scripts/system/toast.js` + `ui/hud_screen.json`): заголовок `/title` с невидимой меткой `§s§f§o` в начале рисуется не по центру, а плашкой снизу посередине; обычные заголовки — как в игре. Actionbar занят панелью слева, поэтому плашка работает через канал title.
* **Мини-игры** (`scripts/system/minigames.js`, Меню сервера → Мини-игры, `!game`): основа для мини-игр — запись, отсчёт (заголовком на экране), игра, выбывание (смерть, выход с сервера или правило игры), победитель с наградой и +1 к `stat_wins` и `stat_win_<игра>`, возврат на точку «Мини-игры». Игрок в игре — тег `game:<id>`. Первая игра — **⚔ PvP «Последний выживший»** (значок меча в названии) (`pvp_ffa`, 2–16 игроков): все на PvP-арену, выбывает умерший или ушедший с арены, победителю 5 000 монет и 5 VIP-коинов. Вторая — **Сплиф** (`spleef`, `scripts/system/spleef.js`, 2–16 игроков, награда как в PvP): башня из 4 снежных этажей (центр x 501, z 502; этажи y −13, −23, −33, −43 — бывшие бетонные полы, перед игрой и после неё заливаются снегом заново по точной форме полов карты; башню держит прогруженной ticking area `spleef`). Игроки встают по кругу на верхнем этаже, в слоте кирки — алмазная лопата, которая копает только снег (закреплена в слоте, в магазине лопаты не зачаровываются); урона нет (сопротивление 255 на время игры). Провалился ниже нижнего этажа (y < −44,5) — выбыл и до конца игры смотрит со стеклянной крыши (501 −3 502); телепорт (`!warp`, `!tp`, `!tphere`, меню) и выход из игры участникам и зрителям, пока она идёт, запрещены всем, кроме владельца. Выпавшие снежки убираются сразу у сломанного блока и раз в секунду по всей башне; заливка (больше сотни команд `fill`) идёт порциями по 8 команд за тик — иначе переполняется очередь команд скриптов («command queue is full»); кирку уровня возвращает `functions/system/pickaxe_lvl` (табло `pick` = 0), снег в сплифе не считается в `stat_mined`. Новая игра — `registerGame({ id, minPlayers, maxPlayers, start, isOut, reward, onStart, onEnd, cleanup, spectate, lockTeleport })` и ключ `minigame.<id>.name`. Администратор: `!game start|stop <игра>`.
* **Проверка CPS** (`scripts/system/cps.js`): на PvP-арене каждый видит свой CPS и скорость («CPS: 7 • 4.3 м/с» — по горизонтали за последнюю секунду, после телепорта — прочерк), а в бою — и здоровье противника («• HP: 14»: последний, кого ты ударил или кто ударил тебя, 10 секунд; зелёное, оранжевое ниже 60 %, красное ниже 30 %; обновляется дважды в секунду) строкой над хотбаром (зелёный, оранжевый у предела, красный на пределе; метка `§s§f§c`, ниже плашки достижений и не перебивает её). Удары по сущностям в секунду; 3 секунды подряд не меньше предела (16, меняется `/scoreboard players set cps_limit settings <число>`) — хелперам и выше в сети предупреждение (не чаще раза в 30 секунд на игрока). `!cps <ник>` — сейчас и максимум за 10 секунд. Сам не наказывает.
* **Античит** (`scripts/system/anticheat.js` — очки, сигналы, режим, инвентарь; `scripts/system/anticheat_checks.js` — движение, удары, копание). Восемь проверок: запрещённые предметы (командные и структурные блоки, барьер, блок света, яйца призыва, оседающие зелья и др.); невозможные предметы (уровень чар выше максимума, несовместимые чары — острота с небесной карой, чары не для этого предмета, стопка больше возможной); дальность удара (больше 6 блоков от глаз до хитбокса); удар не глядя (цель вне поля зрения или три цели за полсекунды); скорость (больше 10 м/с по горизонтали за секунду; с эффектом «Скорость» и на льду предел выше); полёт (больше секунды в воздухе без падения); сквозь блоки (голова и ноги в твёрдом блоке дольше секунды и движение там — застрявшего не трогает); быстрое копание (5 блоков за тик или больше 30 в секунду — VIP-кирки копают мгновенно, поэтому порог высокий). Нарушение даёт очки (VL), очки тают: −1 за 5 секунд, выход из мира их не сбрасывает. На пороге проверки (1 у предметов, 3 у дальности и сквозь блоки, 4 у удара не глядя, 5 у скорости и полёта) хелперам и выше приходит сигнал (не чаще раза в 15 секунд на игрока и проверку); игрокам сигналы не видны, сам нарушитель получает сообщение только об удалённом предмете. Режим — `/scoreboard players set ac_mode settings <1|2|3>` или `!ac mode <alerts|rollback|kick>` (администратор): 1 — только сигналы; 2 — сигнал + откат (по умолчанию): движение — возврат на последнее честное место на опоре, удар — урон возвращается жертве, быстрое копание — только сигнал (добыча и деньги уже начислены); 3 — откат и кик, когда очки втрое выше порога. Запрещённые и невозможные предметы удаляются в любом режиме. Не проверяются владелец, администраторы, бот, творческий режим и наблюдатель. Чтобы не ловить честных: после телепорта (больше 8 блоков за тик — команды, варпы, жемчуг, мини-игры) и после урона (отбрасывание, взрыв) движение 2 секунды не проверяется; рядом с водой, лавой, лестницей, лианами, паутиной, лесами, слизью и мёдом, с элитрами на груди (тег `ac:elytra`, ищется командой раз в 2 секунды), с трезубцем «Тягун» в руке, с левитацией и плавным падением, у замороженных — тоже. Ограничение: скрипт 1.19.50 не видит, едет ли игрок в лодке или вагонетке. Предметы VIP-лавки сверяются по типу, имени и потолку каждого зачарования из сундуков лавки (кирки #1/#2/#3 — эффективность 10/20/30 и удача 5/10/15, головы — защита X); раньше хватало одного имени, и переименованный на наковальне меч проходил с любыми чарами. `!ac` (хелпер и выше) — режим и игроки с очками, `!ac <ник>` — очки по проверкам, `!ac reset <ник>` (модератор) — сбросить.
* **Музыка** (`scripts/system/music.js`, Настройки → Музыка): фоновую музыку играет игра (`music.game` в `sound_definitions.json` заменён на `music/main.theme`); у выключивших — `stopsound @s music.game` раз в 2 секунды (тег `player:music_off`).
* Идеи достижений и мини-игр — по мотивам карты FearCube (с разрешения автора, MisterFear2023), код свой.

### ⚔️ 5. PvP и выживание
* **PvP только на арене**: `minecraft:damage_sensor` в `entities/player.json` — урон между игроками проходит, только если у обоих тег `player:pvp` (выдаётся по координатам арены).
* **Вход на арену** (`scripts/system/pvp.js`): `!warp pvp` и портал из мини-игр ставят игрока в случайную точку площадки (x 245–335, z 260–340) на ближайший к высоте −25 пол, чтобы игроки не появлялись друг у друга.
* **Режим боя**: кто получил или нанёс урон другому игроку на арене, 15 секунд не может уйти телепортом (`!warp`, меню телепортаций); модератор может забрать игрока командой `!warp <точка> <ник>`.
* **Голод только на арене**: вне арены у игрока группа компонентов с нулевым расходом голода (`server:hunger_off`), на арене — ванильная.
* **Без опыта с руд**: сферы ванильного опыта удаляются сразу; прогресс карты — своё табло `xp`.
* **Зона командных блоков** (x 50, z 50, радиус 25): только владелец, администраторы и боты (`role:bot`); остальных `system/system` переносит на спавн.

### 🔐 6. Аккаунты и роли
* **Регистрация и вход** (`scripts/register/`): до входа чат, команды и меню недоступны; одна форма за раз.
* **Пароли** хранятся не открытым текстом, а как соль и хеш SHA-256 (теги `auth:salt:` / `auth:hash:`); длина 5–32 символа. Старые открытые пароли переводятся в хеш при первом входе.
* **Смена пароля** (`scripts/register/change.js`): Меню сервера → Настройки → «Сменить пароль» или `!password` — старый пароль, новый, повтор; после 3 неверных старых паролей — пауза 60 секунд.
* **Правила** (Меню сервера → Правила): 11 пунктов — нарушение и наказание со сроком (мут, предупреждение, тюрьма `!jail`, кик, бан); третье предупреждение — кик, срок персонал выбирает в пределах указанного. Строки — `menu.rules.line.N`, число пунктов — `RULES_COUNT` в `scripts/menu/main_menu.js`.
* **Сброс забытого пароля** — только владелец (`!resetpass <ник>` или карточка игрока в меню администратора) и только игроку в сети: пароль стирается, игрок сразу проходит регистрацию нового, персонал в сети получает сообщение. Прогресс не трогается. Сброс игроку не в сети запрещён: иначе аккаунт мог бы занять любой, кто зайдёт под этим ником.
* **До входа** — слепота и замедление на 60 секунд с обновлением раз в 10 секунд (раньше 2 секунды раз в секунду — экран мигал); после входа эффекты снимаются (замедление замороженного — нет).
* **Роли** (`getRole()` / `hasRole()` в `DataBase.js`): Игрок → Модератор → Администратор → Владелец, каждая следующая умеет всё, что предыдущая.
  * Владелец — хост мира (тег `role:owner`; выдаётся вручную: `/tag <ник> add role:owner`), он один. Хелпера, модератора и администратора назначает он: `!role <ник> <player|helper|moder|admin>` (тег `role:helper` / `role:moder` / `role:admin`), `!roles` — роли игроков в сети. Порядок ролей: игрок < хелпер < модератор < администратор < владелец.
  * Игрок: `!help [команда]`, `!warp [точка]` (без точки — список: спавн — всегда 0 5 0, шахта по уровню — 1–15 у спавна, 16–25 адская, 26–40 третья, мини-игры, PvP-арена, сплиф, тир — туда же ведёт зелёный портал в лобби мини-игр (−109 0 −51; белый — сплиф, красный — PvP-арена); те же точки — в Меню сервера → Телепортации; локация босса — пока только персоналу), `!emotes`, `!msg`, `!reply` (ответ в ЛС), `!clearchat` (только себе), `!balance`, `!pay <ник> <сумма>` (как перевод в банке), `!top <money|lvl|rebirth|vip_coins|kd|pvp|spleef>` (топ-5 в сети; `kd` — убийства/смерти, `pvp` и `spleef` — победы в мини-играх; без аргумента — подсказка), `!game [join <игра>|leave]` (мини-игры) и `!online` (игроки в сети), `!stats [ник]`, `!report <ник> <причина>` (модераторам в сети, не чаще раза в минуту), `!rules`, `!password` (смена пароля).
  * Срок наказания (`!mute`, `!jail`, `!ban`): число — минуты, или `30m`, `2h`, `1d` (до 30 дней), или `permanent` — навсегда, до снятия командой (`parseTerm()` в `DataBase.js`).
  * Хелпер (наблюдение и тюрьма): `!jail <ник> <срок|permanent> [причина]` / `!unjail <ник>` (тюрьма — камера у спавна x −20…−16, z −4…0, `scripts/system/jail.js`: вышедшего из камеры раз в 5 тиков возвращает обратно; в тюрьме недоступны меню, `!warp`, `!tp` и мини-игры; срок истёк — на спавн; тег `state:jail:<окончание|permanent>`, выпустить раньше может роль не ниже посадившей), `!tp <ник>` (к игроку) или `!tp <x> <y> <z>` (в точку, можно `~` — относительно себя), `!invis`, `!gm6` (себе), `!cps <ник>`, `!ac [ник]`; ему приходят жалобы (`!report`), предупреждения CPS и сигналы античита. Ник — тёмно-бирюзовый (`§3`; этот цвет продаётся в Косметике, поэтому за ролью не закреплён — защищено только название «Хелпер» в префиксе).
  * Модератор: всё, что у хелпера, и `!tphere`, `!gm6 <ник>`, `!warp <точка> <ник>` (отправить другого), `!clearchat all`, `!kick`, `!mute <ник> <срок|permanent> [причина]` / `!unmute` (когда время мута истекло, игроку приходит сообщение, что писать снова можно), `!warn <ник> <причина>` (третье — кик), `!unwarn <ник> [число|all]`, `!freeze <ник>` (игрок застывает на месте, даже в воздухе; недоступны меню, меню администратора и `!warp`) / `!unfreeze <ник>`, `!cps <ник>` (проверка на автокликер) — наказывать можно только игроков с ролью ниже своей. Снять мут, заморозку или предупреждения может только роль не ниже выдавшего (теги `state:mute_by:`, `state:frozen_by:`, `state:warn_by:`). Мут, предупреждения и заморозка хранятся тегами (`state:mute:<окончание>`, `state:warn:N`, `state:frozen`) и переживают перезаход.
  * Администратор: режимы игры и `!fly` себе и другим (креатив, наблюдатель, полёт и палочку админа другому — только тому, чья роль сама даёт эту команду: игроку и модератору креатив не выдать, наблюдатель модератору — можно; приключение и выключение полёта — любому), время (словом или числом), бот, палочка админа (`!stick`: ПКМ по игроку на ПК или кнопка «Взаимодействовать» на телефоне — кик), префиксы (`list`/`clear`), теги (`list`, без служебных тегов паролей), `!debug [ник]` (роль, позиция, главные счета и теги игрока по группам — `[role]`, `[state]`, `[fx]`…), `!achievement <ник> list|grant|revoke [id]`, `!game start|stop <игра>`, `!color <ник> <name|text> <цвет|reset>` (цвет ника в чате и над головой или текста сообщений; цвета ролей — тёмно-красный, красный, синий — только тем, у кого эта роль; словом — `aqua`, `gold`… — или кодом `b`, `6`…; то же в меню администратора → Игроки → «Цвет в чате»), табло (`!scoreboard <ник> add|remove|set|get|list|reset [табло] [число]`, `!scoreboard objectives`; табло и число проверяются, в ответе — новое значение; служебные табло `timer`, `system`, `settings`, `display`, `online`, `xp_need` и сброс всех счетов сразу — только владельцу), `!event <haste|rain|gift>` (ивент сразу, даже если выключен в `settings`), `!boost <x2|x4> [1–60 мин]` (бесплатно), `!boost magnet [ник] [мин]` (личный «Магнит руды» себе или игроку), `!say` (объявление от сервера), точки `!warp vip` и `!warp cmd`, `!ban <ник> [срок|permanent] [причина]` — бан по нику (без срока — навсегда; истёкший бан не действует и убирается из списка, в тексте кика — оставшиеся минуты) (игрока выгоняет при каждом входе под этим ником; ник на пиратском клиенте меняется свободно, а вместе с ним и номер игрока в мире `player.id`, поэтому от смены ника бан не спасает — по устройству Script API 1.19.50 банить не умеет), `!unban <ник|номер>`, `!banlist`; владельца забанить нельзя, список — в свойствах мира `shop:bans0…3`, меню администратора (выдаётся в 7-й слот); античит его не проверяет, режим приключения не навязывается.
  * Владелец: `!role`, `!roles`, `!resetpass <ник>`, `!resetoffline` (всё сбросить игрокам **не в сети**: все теги — и роль, и пароль, им придётся зарегистрироваться заново — и все счета; игроки в сети не затрагиваются; сначала сводка, выполнение — `!resetoffline confirm` в течение 30 секунд. Счета: `reset *` в каждом табло, затем счета игроков в сети и служебные записи вроде `settings` возвращаются; теги — при входе: номер сброса в свойстве мира `shop:offline_reset_id`, отметка `sys:offline_reset:<номер>`, `scripts/system/offline_reset.js`), `!wipe` (сначала сводка — что сбросится, что останется и скольких игроков затронет; выполняется только после `!wipe confirm` в течение 30 секунд) и вайп в меню администратора. Вайп (`scripts/system/wipe.js`) сбрасывает прогресс (уровень, опыт, монеты, VIP-коины, ребитхи, зачарования, промокоды, бусты), достижения и косметику; роли, пароли, баны, наказания и настройки остаются. Счета сбрасываются у всех сразу (`functions/system/wipe`, `scoreboard players reset *`), теги — у игроков в сети сразу, у остальных при входе: номер вайпа хранится в свойстве мира `shop:wipe_id`, сброшенный игрок получает тег `sys:wipe:<номер>`. Скрипты и функции без перезахода перезагружает ванильный `/reload` (вручную: из скрипта команда недоступна); после загрузки скриптов `system/reload.js` пишет администраторам в сети «Скрипты загружены» — `console.log` окно журнала не показывает. `.lang` и текстуры — только перезаходом.
  * **Меню администратора** (`scripts/menu/admin_menu.js`) выполняет те же команды, что и чат (`runChatCommand()` из `chat/commands.js`), — с теми же проверками прав и сообщениями:
    * «Игроки» — выбор игрока в сети, карточка (роль, уровень, монеты со значком монеты, предупреждения) и действия: статистика, телепорт к нему / к себе, спавн, режим игры, монеты, заморозка, мут / снятие мута, тюрьма / «Выпустить» (в карточке — остаток срока), предупреждение, кик, бан; у мута, тюрьмы и бана срок выбирается списком (минуты, часы, дни или «навсегда»; у бана по умолчанию — навсегда); роль — только владелец;
    * «Бусты и ивенты» — общий буст x2/x4 и «Магнит руды» любому игроку — время списком (5, 10, 15, 20, 30, 45, 60 минут), запуск ивента, переключатели ивентов по таймеру; «Отключить выданные бусты» (и `!boost stop`) — с подтверждением снимает общий буст и магниты, выданные отсюда или командой, по ошибке; купленные игроками не трогаются (`scripts/system/boosts.js`: общий буст администратора — свойство мира `shop:admin_boost` с временем окончания, магнит — тег `boost:magnet_admin`);
    * «Сервер» — сводка: онлайн, персонал, идущий буст с остатком времени, какие ивенты по таймеру включены; топ игроков по монетам, уровню, ребитхам, VIP-коинам, K/D, победам в PvP или в сплифе;
    * «Бот» — призвать, убрать, переименовать (имя хранится в свойстве мира `shop:bot_name`; бот в мире появляется заново под новым именем), телепорт бота к себе и себя к боту, сообщение в чат от имени бота (в формате обычного чата), «Управление слотами» (сразу под «Написать от имени бота») — хотбар 1–9 (можно сразу взять в руку), вторая рука и 4 слота брони: ID предмета, количество, метаданные, пустой ID — очистить слот; эффекты на бота — любой из 30 эффектов 1.19.50, в том числе отрицательные (усиление ползунком 0–255, как у `/effect`: 0 — уровень I; время списком от 30 секунд до «бесконечно»; с частицами или без) и «Снять все эффекты»; у бота (тег `role:bot`) в чате всегда префикс «Бот» — роли и ранги его не перебивают, `!role` боту не выдаётся; `!bot` призывает бота к себе, если его ещё нет, `!bot settings` открывает это же окно управления ботом (после закрытия чата);
    * а также режим игры и переключатель полёта, время, телепортации (три шахты, VIP, мини-игры, PvP-арена, сплиф, тир, локация босса, CMD Zone, случайный игрок), 12 эффектов, инструменты (командные блоки всех видов, блок-пазл, портативный кристалл Энда и др.; «Выбрать предмет по ID» — ID, количество и метаданные, несуществующий предмет — сообщение об ошибке; очистка инвентаря — с подтверждением), объявление (как `!say`, пустое не отправляется); «Вайп» есть только у владельца: внутри — «Полный вайп» и «Сброс статистики игроков вне сети» (как `!resetoffline`), у каждого окно «Да / Нет» (`wipeConfirm()` в `forms.js`).
  * **Крестик** в любом разделе меню сервера и меню администратора возвращает на уровень вверх, как «Назад»; в главном меню — закрывает его (`closedByPlayer()` в `DataBase.js`).
  * В чате перед уровнем — префикс роли («Владелец», «Админ», «Модератор»), ник в цвете роли (тёмно-красный, красный, синий), над головой тоже; свой тег `name:` важнее цвета роли.
  * `!help` показывает каждому только доступные ему команды — сплошным списком в порядке `commandsList` (по ролям, внутри роли по смыслу). Префикс из `!prefix` (`rank:`) — отдельное украшение и прав не даёт.

### 🌍 7. Локализация
* **4 языка**: русский, английский, украинский, испанский — одинаковый набор ключей во всех `.lang`.
* **Ключи перевода** по схеме `раздел.экран.элемент`, строчными, слова через `_`:
  * `menu.*` — меню игрока (`menu.shop.kits.title`, `menu.main.button.bank`, `menu.howtoplay.line.7`), `admin.*` — меню админа, `account.*` — формы входа и регистрации;
  * `chat.*` — сообщения в чат (`chat.boost.x2`, `chat.bank.error.self`, `chat.help.warp` — описания для `!help`), `screen.*` — заголовки на экране (`titleraw`), `hud.*` — панель слева;
  * ванильные ключи (`item.*`, `tile.*`, `death.*`, `multiplayer.*` …) переопределяются под своими именами; `scoreboards.map`, `scoreboards.x2boost`, `scoreboards.x4boost` — имена строк табло справа, они хранятся в мире, поэтому не переименованы.
* **Целые фразы с параметрами**: ник, числа и т.п. подставляются в `%1$s`, `%2$s` через `"with"` (в функциях — `{"selector":"@s"}` / `{"score":…}`, в скриптах — `rawTranslate()`), а не склеиваются из кусков — каждый язык сам выбирает порядок слов.
* **Единый стиль сообщений в чате**: `иконка Метка » текст`.
  * У каждой метки свой цвет; в игре они называются `LvL UP`, `Магазин`, `Буст`, `Ивент`, `Банк`, `Промокод`, `Сервер`, `Аккаунт`, `Настройки`, `CMD`, ошибки — `✕ ERROR! » …`.
  * Текст после `»` по одному шаблону: серый `§7`, ник белым `§f`, числа и названия жёлтым `§e`, «включено/выключено» — зелёным/красным.
  * Иконки — из шрифта карты (`glyph_E1`/`glyph_2A`), те же, что в меню; к игроку обращаемся на «ты».
  * Сообщения со вставкой ключа (`%ключ`) скрипты отправляют через `tellText()` — то есть `tellraw` с переводом, а не обычным текстом.
* **Единый стиль меню**: заголовок `Раздел » иконка Подраздел`, кнопки `§8иконка Название`, под ними вторая строка (цена, ник, «[Нажми, чтобы открыть]»); цветные кнопки — только там, где цвет что-то значит. Текст окна — описание без «Выбери…» в конце; в Настройках под ним — «Текущее состояние».

### Стиль скриптов
* **Формы** — только через `scripts/menu/forms.js`: `showMenu(player, заголовок, текст, пункты, onBack)` (пункт — `{ text, icon, run }`, ложные пропускаются, `backButton()` — «Назад»), `showModal(player, modal(заголовок)…, onSubmit, onBack)`, `confirm()` (Да / Нет), `wipeConfirm()` (Да / Нет с заголовком «Предупреждение» — для опасных действий администратора), `toggleMenu()` (Включить/Выключить с текущим состоянием). Крестик — всегда на уровень вверх; форма, не открывшаяся из-за открытого чата, покажется, когда чат закроют. После нажатия: если в чат пришла ошибка (ключ из `scripts/system/error_keys.js` — все строки с «⩕ ERROR!», файл собирается по `ru_RU.lang`), закрывается вся цепочка меню; если сообщение об успехе — остаётся одно последнее окно: форма, которую действие открывает следом, а если она не открывается — то же меню снова (окно с полями и «Да / Нет» — возвращает в своё меню). Покупки через `.mcfunction` пишут в чат сами — скрипт этих сообщений не видит, после них окно закрывается. Общие ошибки — одна строка на все команды: `chat.cmd.error.number` (число вне диапазона, с границами), `not_found` (с подсказкой, где список), `self`, `role`, `offline`, `confirm_expired`, `no_permission`. В формах 1.19.50 у ключей нет параметров, поэтому ник ставится так, чтобы порядок слов подходил всем языкам (в регистрации — в начале строки).
* **Сообщения** — `tell(player, 'ключ', …аргументы)` из `DataBase.js` (аргумент — строка, число или `{ translate }`); текст с `%ключами` — `tellText(player, текст, { ключ: [параметры] })` (параметры — `%1$s` в .lang, например ник и пароль при регистрации); команды — `run(entity, команда)`, ошибка не попадает в журнал.
* Одинарные кавычки, `===`, точка с запятой, табуляция; у каждого файла — шапка `// --- Что это ---`. Проверяется `eslint` (правила semi, quotes, eqeqeq, indent, no-unused-vars).

### Названия тегов и табло
Теги — `группа:значение` строчными буквами, слова через `_`:

| Группа | Теги | Что значит |
|---|---|---|
| `role:` | `role:owner`, `role:admin`, `role:moder`, `role:helper`, `role:bot` | роль (владельца выдают вручную, остальных — `!role`) |
| `auth:` | `auth:login`, `auth:register`, `auth:done`, `auth:salt:…`, `auth:hash:…` | вход и пароль |
| `state:` | `state:frozen`, `state:frozen_at:…`, `state:mute:…`, `state:warn:N`, `state:<вид>_by:<роль>`, `state:fly`, `state:invis`, `state:kick` | наказания и состояния игрока |
| `boost:` | `boost:x2`, `boost:x4`, `boost:magnet` | действующие бусты |
| `player:` | `player`, `player:pvp`, `player:rebirth`, `player:board…`, `player:sound`, `player:particle`, `player:music_off`, `player:haste` | игрок и его настройки |
| `sys:` | `sys:buy_ok`, `sys:pick_update`, `sys:rebirth_now`, `sys:hunger_off`, `sys:pvp_v2`, `sys:warp_pvp`, `sys:wipe:<номер>`, `sys:offline_reset:<номер>`, `sys:wins_split` (прежние победы перенесены в `stat_win_pvp_ffa`) | служебные отметки функций |
| `rank:` | `rank:<префикс>` | префикс в чате (`!prefix`) и уровень |
| `ach:` | `ach:<id>` | полученные достижения (`scripts/system/achievements.js`) |
| `game:` | `game:<id>`, `game:watch` | игрок записан в мини-игру; выбыл и смотрит игру (сплиф) |
| `stat:` | `stat:paid` | переводил монеты (достижение «Щедрая душа») |
| `chat:` | `chat:name_color:<код>`, `chat:text_color:<код>` | цвет ника (в чате и над головой) и текста сообщений (`!color`); код — символ после «§», `0`–`9`, `a`–`g` |

Табло — короткие слова через `_`: `lvl`, `xp`, `xp_need` (опыт до следующего уровня; до 0.3.0 — `qx`), `money`, `vip_coins` (VIP-коины; до 0.3.0 — `money2`, так оно и осталось в неактивных командных блоках VIP-магазина), `rebirth`, `efficiency`, `fortune`, `magnet` (секунды магнита руды; до 0.3.0 — `tpore`), служебные `system`, `timer`, `settings`, `display`, `online`, `promo1…4`, `pick`; счётчики `stat_*` (см. «Достижения»; `stat_deaths`, `stat_win_pvp_ffa`, `stat_win_spleef` создаёт `functions/system/setup` версии 5).

Старые названия тегов (до 0.3.0: `host`, `hasRegister`, `frozen`, `mute:`, `x2boost` и т. д.) меняет на новые `scripts/system/migrate.js`, когда игрок заходит; старые табло `qx`, `tpore` и `money2` удаляет `functions/system/setup` (`setup system` = 3; VIP-коины игроков в сети переносятся в `vip_coins`).
`!tag` не меняет теги `role:…` и `auth:…`.
**Защита от самозванцев:** ник цвета роли (тёмно-красный — владелец, красный — администратор, синий — модератор) и префикс с цветом или названием роли («Админ», «Moderator», «Бот»…) можно выдать только тому, у кого эта роль есть, — через `!color`, `!prefix` и `!tag` одинаково. Если роль сняли (или тег выдан в обход), такой цвет и префикс просто не показываются.

## 🛠 Установка и разработка
Репозиторий содержит два пака — их нужно разложить по своим папкам, а не клонировать целиком в одну:

1. `behavior_packs/main-addon-shop_for_ore` → `development_behavior_packs/` (или `behavior_packs/` внутри папки мира).
2. `resource_packs/main-rp-shop_for_ore` → `development_resource_packs/` (или `resource_packs/` внутри папки мира).
3. Подключите к миру пак ресурсов и пак поведения (пак `server-ui` из старых версий больше не нужен — его табло теперь в основном паке). Для Script API в настройках мира должны быть включены экспериментальные функции (переключатель «Beta APIs»).

### Что не входит в репозиторий
* **Шрифты** (`resource_packs/main-rp-shop_for_ore/font/`) — без них используется стандартный шрифт игры.
* **Звуки** (`sounds/**/*.ogg`) — `sound_definitions.json` ссылается на 4 звука (`challenge.complete`, `tnt.explode`, `glass.broke`, `music/main.theme`); без файлов они не проигрываются.
