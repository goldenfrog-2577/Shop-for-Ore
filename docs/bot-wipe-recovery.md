# Функции, бот и данные после вайпа

В сохранённом level.dat найдены functioncommandlimit=0 и maxcommandchainlength=0. Из-за нулевых бюджетов не выполняются mcfunctions, включая system/spawnbot и восстановление игроков из system/system/timers. commandblocksenabled=false — отдельная настройка, она сохраняется. Скриптовые меню и HUD могут продолжать работать при отключённых функциях.

Разовая миграция shop:command_limits_v1 сначала восстанавливает отсутствующие счета и отметку player у уже сброшенного игрока первого уровня, затем напрямую через Script API выполняет gamerule functioncommandlimit 10000 и gamerule maxcommandchainlength 65536. Это защищает новые деньги от повторной инициализации как новичка при включении tick-функций. Успешная миграция отмечается динамическим свойством; будущие ручные лимиты владельца после миграции при каждой загрузке не переписываются. При ошибке разрешена повторная попытка. GameTest ждёт окончания этой подготовки.

Нативные ошибки function system/spawnbot теперь пишутся целиком, включая синхронное исключение и отклонённый промис. Общая обёртка run больше не скрывает причину отказа именно в этой диагностической точке. Загрузка площадки, дедупликация, подтверждение появления/телепортации и тайм-аут 100 тиков сохранены.

В копии базы мира подтверждались отсутствующие xp, rebirth, online, efficiency, fortune, pick и xp_need при уже существующих новых money/vip_coins/play_seconds. player_scores.js восстанавливает отсутствующие записи и цели раз в секунду, обрабатывает исключение SDK и undefined. Уже имеющиеся деньги, VIP-монеты и время не обнуляются. Сигнал ребитха снятым player при уровне 25+ сохранён. Будущий полный вайп выполняет команды последовательно и явно записывает нули/уровень 1 игрокам в сети. Повторный вайп для ремонта не нужен.

Тест command_limits.mjs воспроизводит отказ функции при двух нулевых бюджетах, затем проверяет восстановление счетов до включения функций, запуск функции после ремонта, неизменность commandblocksenabled, одну миграцию, сохранение последующих настроек и повтор после нативной ошибки. bot_spawn.mjs проверяет полный текст ошибки движка. Остальные проверки включают восстановление данных, ребитх, тайм-ауты/отказы/отмену и поведение меню.

Для текущего запуска можно вручную выполнить /gamerule functioncommandlimit 10000 и /gamerule maxcommandchainlength 65536. Для автоматической миграции нужен перезаход в мир, чтобы зарегистрировать новое динамическое свойство. Владелец подтвердил в клиенте: после этих двух команд бот появился. Автоматическую миграцию нужно проверить после перезахода.

level.dat и рабочая база не редактировались: настройки прочитаны в копии, исправление выполняется движком при запуске скрипта. NPC-индекс мира сохраняется отдельно от репозиторного; шрифты и звуки не публикуются.
